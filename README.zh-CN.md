# DynamicLore 3 — SillyTavern 世界书助手

[English](README.md) · [上游审计与验收清单](docs/AUDIT.md)

使用 **SillyTavern 当前连接的模型**，把对话事实整理成世界书建议。先查看、编辑完整条目，再决定是否写入；待审队列和近期撤销记录随聊天保存。无需额外 API Key，运行无需安装 npm 依赖或执行构建。

**版本 3.0.0**——无需构建，已加入回归测试并验证 SillyTavern 实际浏览器流程。

## 安装

要求 **SillyTavern 1.18.0 或更新版本**、可用的模型连接，以及已打开的角色聊天或群聊。已验证的 release 基线为 [`8172dcd0ee672d3cd9a5e5f7af134f91a45cd2b8`](https://github.com/SillyTavern/SillyTavern/blob/8172dcd0ee672d3cd9a5e5f7af134f91a45cd2b8/package.json)，包版本为 `1.18.0`。不支持更早版本，实际验证范围见下方报告。

在 SillyTavern 的扩展安装器中输入：

```text
https://github.com/LiweiDonVee/Extension-DynamicLore
```

安装默认的 `main` 分支。本地安装请将**整个仓库**放入当前用户扩展目录，例如 `data/default-user/extensions/Extension-DynamicLore/`，然后刷新 SillyTavern。只启用一份扩展，不要只复制 `index.js`，也不要通过 `file://` 直接打开。

扩展使用浏览器原生模块，宿主适配器加载 SillyTavern 的 `/scripts/world-info.js`，通过当前上下文和同源后端读写。运行不需要 `npm install`、webpack 或生成 `dist/`；开发检查需要 Node.js 20+。

## 使用

1. 打开聊天，从扩展菜单进入 **DynamicLore**，或输入 `/dynamiclore`。
2. 选择目标世界书，或新建一本。新建会关联当前聊天，并设为明确指定的目标。
3. 点击 **Analyze（分析）**。模型读取有长度限制的对话和选中的已有知识，提出角色、地点、物品、规则／概念和事件等条目建议。
4. 对照原条目和**完整的替换内容**，编辑标题、正文及建议关键词，然后接受或拒绝。也可批量审阅。
5. 在历史中撤销近期接受的修改，或导出当前聊天的审阅数据。

接受会写入建议最初绑定的世界书；拒绝不会修改世界书正文。更新使用审阅后的完整正文替换旧正文，不再直接追加。原激活关键词会与建议关键词合并，其他无关字段保留。请检查是否遗漏重要事实；需要删除旧关键词时，请使用 SillyTavern 世界书编辑器。

### 目标优先级

自动选择顺序为：**明确指定的目标 → 聊天关联世界书 → 角色主世界书 → 唯一的全局已选世界书**。群聊跳过角色世界书，不会随发言角色切换目标。无目标、书不存在或全局候选不唯一时，需明确选择，不会使用无关的书作为替代。书名支持空格和中文。

明确指定的目标会跨聊天保留，优先于聊天关联；`/dynamiclore book auto` 可清除它。已有建议始终绑定分析时的聊天和书，之后修改设置不会转移其写入位置。群聊的身份和队列也不会随当前发言角色变化。

## 设置与自动分析

| 设置 | 全新安装的默认值／含义 |
|---|---|
| 启用扩展 | 开启，可手动分析 |
| 自动分析 | **关闭** |
| 分析间隔 | 5 个新的助手回合，可设为 1–100 |
| 自动接受 | **关闭**，与自动分析分别控制 |
| 自动接受置信度 | 默认 `0.9`；达到或超过所设阈值（**>=**）即可自动接受 |
| 对话窗口 | 有长度边界且可配置，与触发间隔分别设置 |
| 输出控制 | 语言、条目类型、自定义指令、回复长度和建议数量限制 |

自动分析按新的助手回合计数，在生成结束后触发。用户消息、开场白、重复渲染、切换候选回复（swipe）和续写不增加计数。编辑、删除或切换候选回复会使旧的待审建议及相关的进行中分析失效，并重置跟踪；请重新分析后再接受新建议。**这是有意改变的语义：** 上游按用户和角色的渲染事件共同计数；现在“5”表示五个符合条件的助手回合。

自动接受需要主动开启，仍受验证和冲突检查约束。置信度是模型自行估计的分数，不是经过校准的正确概率。上游使用固定 `> 0.8`；v3 改为可配置阈值，默认 `>= 0.9`。

**取消只丢弃结果，不中止网络请求。** 请求结束前扩展仍处于忙碌状态，模型可能继续运行或计费。切换聊天也会阻止旧分析结果被应用。

## 命令

在 SillyTavern 聊天输入框中使用。含空格的书名可直接输入，也可加引号。

| 命令 | 用途 |
|---|---|
| `/dynamiclore` / `/dynamiclore help` | 打开面板／显示帮助 |
| `/dynamiclore analyze` | 分析当前聊天 |
| `/dynamiclore status` | 查看状态、目标、错误及待审建议 ID |
| `/dynamiclore enable` / `disable` | 启用／停用扩展 |
| `/dynamiclore auto on` / `off` | 开启／关闭自动分析 |
| `/dynamiclore interval 5` | 设置助手回合间隔 |
| `/dynamiclore book "我的世界"` | 选择已有世界书 |
| `/dynamiclore book auto` | 清除明确指定的目标 |
| `/dynamiclore create "我的世界"` | 新建世界书并关联聊天 |
| `/dynamiclore accept ID` / `accept all` | 接受一条／全部待审建议 |
| `/dynamiclore reject ID` / `reject all` | 拒绝一条／全部待审建议 |
| `/dynamiclore undo ID` | 使用历史记录 ID 撤销修改 |
| `/dynamiclore retry` | 重试保存并验证聊天审核记录 |
| `/dynamiclore cancel` | 丢弃进行中分析的结果 |

接受／拒绝使用 status 中的建议 ID；撤销使用历史或导出数据中的历史记录 ID。自动接受及其阈值在面板设置中配置。

## 迁移、恢复与冲突

- **升级：** 通过 SillyTavern 备份相关聊天和世界书，再替换旧安装，只启用一份扩展并刷新。旧设置会规范化，有效的既有选择可能保留。全新安装默认关闭自动分析，**不代表**升级时会重置原先开启的设置，请检查。
- **旧数据：** 已写入的知识仍在原书中。v1/v2 没有保存 v3 队列或撤销快照，旧的未保存卡片和历史修改无法重建为 v3 历史，需要重新分析。
- **队列／历史：** 建议保存在聊天元数据中。每个聊天最多保留 100 条待审建议、50 条已处理建议和 50 条历史记录。导出包含审阅／会话数据，**不是整本世界书备份，也没有自动导入恢复功能**。
- **写入失败：** 建议保持待审，可重试。修复错误、检查当前书后再接受。拒绝只改变审阅状态，状态能否持久保存仍取决于聊天元数据保存是否成功。
- **切换聊天时书已写入，或历史保存失败：** 世界书写入与聊天元数据保存是独立操作。扩展设置中最多保留 50 条已完成写入的恢复回执，并绑定原聊天，重新打开该聊天时用于恢复审阅／历史状态。扩展不会把另一个聊天的元数据保存到当前聊天。请返回原聊天，点击**重试保存审核记录**或使用 `/dynamiclore retry`；只重试聊天记录，不重复写入世界书。回执依赖设置保存且保留数量有限，不是事务性备份；编辑器刷新警告也不代表世界书写入失败。
- **冲突：** 接受前重新读取数据并检查原条目。撤销时若条目又被修改，会拒绝撤销，保留后续编辑；新建条目也须通过检查才能撤销删除。请在世界书编辑器中检查后续改动、保留需要的事实、拒绝过期建议后重新分析。没有强制覆盖按钮。
- **新建／关联失败：** 书可能已经创建，只是聊天关联失败。先刷新列表，选择并关联已有书，不要反复创建。

## 限制

核心提示词预算默认是**序列化后的总计 24,000 个字符**，内部可配置范围为 **2,000–80,000**。字符预算不等于 token 数，也不保证每次都会装入这么多内容。调用模型前，运行时还会依据 SillyTavern 当前上下文上限和真实的异步 token 计数检查是否容得下提示词及回复。超限时请缩短对话窗口、回复长度或自定义指令，或选择更大的模型上下文。

有长度上限的提示词不能包含无限长聊天或大型世界书中的所有事实。因预算未进入提示词的已有条目，不允许在该次分析中被更新。常驻／受保护和禁用条目不作为自动更新候选；身份匹配不明确时可能跳过建议。替换内容仍可能遗漏事实或产生幻觉，人工审阅仍有价值。

单实例内的写入会排队，并检查最新读取的数据。但 **SillyTavern 服务器没有针对这些写入的比较并交换（CAS）机制**：其他标签页或扩展可能在读取与保存之间写入，冲突检查不能保证解决所有并发修改。请避免同时编辑同一本书，并保留备份。

未来的 SillyTavern API 变更可能需要更新适配器。固定模型响应的测试只能验证集成流程，不能证明真实服务商兼容性、提取质量或提示词可靠性。

## 验证记录

**107 项回归测试通过**，模块与安装包检查通过，并在隔离的 SillyTavern 1.18.0 中完成浏览器集成验证。测试通过原生 ST 生成函数和真实后端调用固定响应的 OpenAI 兼容测试服务，操作实际审核按钮，验证保存、刷新恢复、撤销、自动事件、聊天命令与故障恢复。已检查桌面和 375px 手机布局。

使用 Node.js 20+，在仓库根目录执行（无需安装 npm 依赖）：

```bash
npm test
npm run check
```
